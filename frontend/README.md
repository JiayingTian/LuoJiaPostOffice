# 珞珈烟火邮局 · 前端联调版

本版已对照后端 `main / 38ea92b` 的 OpenAPI 和实现适配。前端代码位于独立的 `frontend/` 目录，原有入口插画首页未替换。临时样式待 UI 同学的正式页面与素材到位后替换。

## 已完成

- PC 信封悬停浮起并显示两行摘要，双击进入详情；功能按钮悬停柔光。
- 写信、预览、返回修改；空草稿与未完成草稿可保存，草稿保留首尾空白；正式提交按 2–80 字标题、20–1500 字正文校验。
- 注册、登录；启动依次恢复用户与内存中的 CSRF Token。仅 `403 + 40302` 自动恢复一次 Token 并重试一次，复用原请求体与幂等键；普通权限错误不重试。
- 我的信件按后端 `workflowState` 展示／筛选：草稿、待审核、已公开、退回修改；显示退回原因。
- 完整回信入口遵从详情 `allowReplies`，只允许回复原信；详情下显示已公开回信并支持分页。
- 最简管理员审核页面：待审列表、详情、通过、填写原因退回。入口仅对管理员展示，实际权限由后端校验。
- 登录弹窗及请求失败保留当前编辑内容；提交时阻止重复操作；手机基本适配。

草稿与回信的真实数据由后端提供。演示模式仅用于交互检查，不会把信件自动审核通过，也不会向服务器发送内容。

## 最快让后端同学开始联调

在已有 `38ea92b` 后端的仓库中应用交付的 `luojia-frontend.patch`：

```sh
git switch -c feat/frontend-integration
git apply --check luojia-frontend.patch
git apply luojia-frontend.patch
```

先把补丁文件放到仓库根目录，再执行上述命令。检查失败时先解决已有改动／分支差异，不强行覆盖。补丁包含此前的前端基础版，不需要先应用旧补丁。如果已经应用过旧版前端，需合并差异，不能重复套用全部补丁。

需要 Node.js 20 或更高版本。当前前端无需 `npm install`，在仓库根目录运行：

```sh
npm run dev:api
```

打开 `http://127.0.0.1:4173/` 查看首页。首页的“去读信”“时光信笺”“写一封信”和“登录”已接入 `frontend/` 下的联调页面；也可以直接访问 `http://127.0.0.1:4173/frontend/`。

另一个终端按后端说明启动已有数据库与服务：

```sh
cd backend
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

前提是已按 `backend/README.md` 安装依赖、配置本机 MySQL 数据库及 `.env`。上述命令不会替你安装或创建 MySQL。首次需要测试账号时运行 `python -m scripts.create_test_accounts`；已有账号可直接使用。该脚本会重置测试账号密码，不必每次启动都运行。审核使用脚本生成的 `test_admin`。

前端开发服务器将 `/api/v1` 代理到 `http://127.0.0.1:8000`。浏览器访问的前端 Origin 是 `http://127.0.0.1:4173`，后端此 commit 已默认允许它。始终使用同一主机名，不要来回切换 `localhost` 与 `127.0.0.1` 登录。

地址通过环境变量配置，不需要改页面组件。Windows PowerShell 示例：

```powershell
$env:BACKEND_ORIGIN = "http://127.0.0.1:8000"
npm run dev:api
```

`BACKEND_ORIGIN` 不带 `/api/v1`。`FRONTEND_API_BASE` 默认 `/api/v1`，`FRONTEND_MODE` 可设为 `api` 或 `demo`，`PORT` 默认 `4173`。开发代理仅用于本机开发，不作为生产服务器。

## 127.0.0.1 与团队协作

`127.0.0.1` 永远指访问者自己的电脑，`4173` 是前端端口，`8000` 是后端端口。打开网址前必须先启动对应程序。这份代码尚未自动上传 GitHub，也没有自动安装到队友电脑。

- 开发协作：通过 Git 共享代码，每个人可以独立运行本机版本，不必同时登录。
- 本机联调：先由后端同学在她电脑上同时运行前端与后端，检查登录、草稿、审核和回信。
- 多人验收：两台电脑必须连接同一个后端和数据库，才能互相读到信件。后续部署一个团队共用的测试网址；用户可以先后登录，无须同时在线。

独立运行的两套本地数据库不会因为用了同一个 Git 仓库而同步信件。当前开发服务器仅监听回环地址，不提供直接的跨电脑访问。

## 交互演示与测试

```sh
npm run dev
npm test
npm run preview:build
```

`npm run dev` 为本机演示，不依赖后端。构建出的 `dist/luojia-preview.html` 可直接用浏览器打开，始终为演示模式，不能用来验证真实登录或跨设备寄信。

演示草稿存于当前浏览器，真实模式不将信件正文或登录 Token 存入浏览器持久存储。未保存的编辑内容只存在当前页面中，关闭前会提示。

已完成验证：

- 17 项 Node 自动测试通过，覆盖校验、字段、状态、认证、CSRF 一次重试／并发恢复、幂等键、错误处理和本机草稿。
- Chromium 桌面和 390px 触屏检查通过，包含悬停、双击、草稿恢复、预览、回信及离线文件。
- 使用接口响应夹具检查真实接口模式页面：空草稿、刷新恢复、CSRF 自动重试、退回状态、回信权限与列表、管理员退回。

当前执行环境没有运行 MySQL，上述浏览器接口检查使用的是测试响应，不是后端真实数据库联调。后端实际读写、事务、Cookie 和审核结果仍需在配置好 MySQL 的环境验收。

## 本次联调验收顺序

1. 用户 A 登录，保存空草稿／短正文，刷新后继续编辑，不重新登录。
2. 用户 A 提交完整信件，看到“待审核”。用户 B 不能读取待审核正文。
3. 管理员进入顶部“审核”，填写原因退回；A 查看原因、修改、重新提交。
4. 管理员通过；B 从公共信箱读到原信。
5. B 从原信发起完整回信，管理员通过后，A 在原信详情下读到回信。
6. 确认关闭回信的信件无回信入口，回信本身不能继续回复；网络失败保留正文。

## 给 UI 同学

无需为技术联调增加页面设计任务。继续交付已经约定的核心页面图片、独立插画／信封／信纸素材及简单交互文字即可。

保留 PC 悬停摘要、信封浮起、功能按钮柔光和双击详情。详情页在正文后预留回信区域；同类信件卡片可复用，不必另画一套。管理员页、加载、错误、无权限等通用状态由前端先按统一样式实现；动画精确数值没有指定时由前端设置后一起核验。

## 主要文件

- `app.js`：页面、路由、表单和交互；`app.css`：临时视觉样式。
- `api.js`：真实接口；`demo.js`：独立演示数据；`domain.js`：校验与状态。
- `config.js`：静态演示配置；开发时由服务器按环境变量返回运行配置。
- `../tools/dev-server.mjs`：本地服务与代理；`../tools/build-preview.mjs`：离线构建。
- `../tests/`：可重复运行的自动测试。
