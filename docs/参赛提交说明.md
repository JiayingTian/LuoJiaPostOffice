# 珞珈烟火邮局：参赛提交说明

## 作品与运行

参赛组别：壹组。推荐使用静态演示模式评审。解压后在作品目录运行 `npm run dev`（Node.js 20+），打开终端显示的本地网址；无需 `npm install`、数据库或互联网。首页是 `index.html`，信箱在 `frontend/index.html`。`npm test` 运行前端逻辑测试。预览目录可由 `npm run preview:build` 重新生成。

演示版包含公共来信、偶遇随机信、日历、登录演示、写信与草稿、纸张邮票、投递动画、我的信件、编辑删除与回信。公开投递在演示数据中即时可见。演示账号与新增数据在浏览器本地保存，不会在设备或访客之间同步；现场展示请使用同一浏览器。`backend/` 是另行启动的 FastAPI/MySQL 接口实现，其中公开内容仍有管理员审核规则，与静态演示的即时公开流程不同。介绍作品时请说明所展示的模式。

## 技术与第三方库

前端用原生 HTML、CSS、JavaScript，页面未引入 Bootstrap、Element UI 或其他预设样式库，也未通过 CDN 加载脚本。Node.js 自带模块提供本地预览服务器与打包脚本；前端不依赖 npm 包。后端依赖与用途：FastAPI（HTTP 接口）、Uvicorn（ASGI 服务）、SQLAlchemy（数据库 ORM）、Alembic（数据库迁移）、PyMySQL（MySQL 驱动）、pydantic-settings（配置读取）、argon2-cffi（密码哈希），版本范围见 `backend/requirements.txt`。这些是功能库，不提供页面预设样式。

## 规格与验收

赛事指定 Chrome 129，宽度选项为 1920、1440、720；作品使用响应式布局。`npm test` 验证数据与路由逻辑；最终仍须在赛事指定 Chrome 129 上分别检查这三个宽度，以及正常/慢速网络下的页面、图片和投递流程。为降低慢网加载量，十张最大装饰图已转为 WebP；所有页面图片均随包附带。页面无外部 CDN 依赖。

## 提交包与待补资料

运行 `npm run contest:package` 生成外层 ZIP（内含完整版与匿名版两个 ZIP）。有队伍信息时提供 `TEAM_NAME`、`CAPTAIN_NAME`、`TEAM_MEMBERS`、`ASSET_SOURCES` 环境变量；未提供时生成的完整版 README 和文件名会标记“待填写”，**不可直接邮件提交**。`TEAM_MEMBERS` 应写组内成员及赛事要求的个人信息；`ASSET_SOURCES` 应逐项说明素材来源、授权与自制部分，不能凭猜测填。匿名版 README 不包含选手姓名、学号、联系方式或仓库账号；如果后续加入任何可识别信息，需重新检查代码和文件元数据。

最终邮件及外层 ZIP：`零杯壹组-队伍名-队长姓名.zip`。内层：`2026-零杯壹组-队伍名-队长姓名-完整版.zip`、`2026-零杯壹组-队伍名-队长姓名-匿名版本.zip`。由队长在规定邮箱提交前，确认赛事具体截止时间与邮件要求。当前代码交付不等于已发邮件。
