# 10 月 20 日设置更新

本文件记录当时 V3 设置方案；当前交互以根目录 README 和正式页面为准。

## 已完成的前端交互

- 离开未保存的写信／预览页面：弹窗提供“保存、暂不保存、继续编辑”。保存完成后再离开；取消不改正文。预览与返回修改之间不弹窗。
- 尚未登录时选择保存：保留正文并打开登录，登录后可再次保存。不在用户登录后擅自跳走。
- 浏览器关闭／刷新受浏览器限制，只能使用系统自带的离开确认，不能显示自定义三按钮弹窗。
- 草稿详情增加“删除草稿”；确认框只显示“删除、取消”。取消后保留原信且不请求删除。
- 写信页增加“允许别人回信”，随保存和提交写入已有 allowReplies 字段。
- 写信页增加“信墙公开／指定用户私密投递”选择。私密投递需要收件人用户名，禁用公开回信，预览明确“仅双方可见”。
- 登录后页头显示“退出登录”；管理员和普通用户共用该入口。有未保存正文时先执行统一的离开提醒，再调用 logout API。

## 私密功能的实际完成范围

真实接口已支持指定用户私密投递、收件人搜索和私人收件箱。本机演示仍只用于界面检查，不构成多用户权限验收。

## 已同步的后端约定

1. `private` 表示仅作者和 `recipientUserId` 指定的收件人可读；其他人（含管理员）访问详情返回 404，且不进入公共列表、回信列表或待审列表。
2. 私密草稿仍为 draft；正式投递为 active + private，submittedAt／publishedAt 均为空，不进入公开审核。我的信件以 workflowState=private 展示“私密已投递”。
3. 公开改私密后立即从公共入口隐藏；私密改公开必须重新提交审核。不得由前端自行改已审核状态。
4. 私密信不接受其他人的回信。作者自己的“允许回信”设置在恢复公开时如何恢复，由接口明确；前端目前记住切换前的选择，私密请求实际关闭回信。
5. 已公开信件修改后统一回到草稿箱并停止公开，再次提交后重新审核。
6. 私密信不允许建立公开完整回信，也不支持转发给第三人。
7. 数据库继续使用 wall/public 与 user/private 的绑定约束；读取权限由后端同时核对作者 ID 或收件人 ID。

以上规则已同步到后端、前端和 OpenAPI。

## 给 UI 同学

不需要画设置中心。写信页增加一个可见范围选择和一个回信开关即可；未保存提醒、删除确认沿用前端统一弹窗。继续提供核心页面和独立素材。

## 测试情况

自动测试覆盖私密请求、收件箱和固定审核原因的接口路径；真实数据库仍需用两个普通账号和一个管理员账号完成端到端联调。
