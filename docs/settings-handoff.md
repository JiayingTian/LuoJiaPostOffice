# 10 月 20 日设置更新

以本文件为准，覆盖上一份 settings-next-step.md 中关于退出登录的计划。

## 已完成的前端交互

- 离开未保存的写信／预览页面：弹窗提供“保存、暂不保存、继续编辑”。保存完成后再离开；取消不改正文。预览与返回修改之间不弹窗。
- 尚未登录时选择保存：保留正文并打开登录，登录后可再次保存。不在用户登录后擅自跳走。
- 浏览器关闭／刷新受浏览器限制，只能使用系统自带的离开确认，不能显示自定义三按钮弹窗。
- 草稿详情增加“删除草稿”；确认框只显示“删除、取消”。取消后保留原信且不请求删除。
- 写信页增加“允许别人回信”，随保存和提交写入已有 allowReplies 字段。
- 写信页增加“公开／私密（仅自己可见）”选择。选择私密时禁用回信；预览明确“不公开”，主按钮改为“保存为私密信件”。
- 不再显示退出登录入口，也不做退出提醒流程。后台原有 logout API 保留，不要求后端删除接口。

## 私密功能的实际完成范围

本机演示已实现私密保存、刷新后读取、继续编辑、我的信件筛选；私密信不进入公共列表。本机演示只有一个模拟身份，不是服务端权限验收。

当前真实接口仍只支持公共信箱。因此真实模式下私密选项标为“暂不可用”并禁用；请求构造也会阻止将私密内容按公开信发送。不能把匿名展示、草稿或给自己发一封人对人消息当作已完成的私密功能。

## 后端需补齐的约定

建议在创建／更新信件契约中增加 `visibility: public | private`（命名与已有响应字段保持一致），并确定以下行为，更新 OpenAPI 后交给前端接入：

1. `private` 表示仅作者可读，非作者（含普通审核管理员）访问详情返回 404，不在公共列表、公共回信列表或待审列表中出现。
2. 私密草稿仍为 draft；正式私密保存可为 active + private，submittedAt／publishedAt 均为空，不进入公开审核。我的信件可用派生 workflowState=private 展示“仅自己可见”。
3. 公开改私密后立即从公共入口隐藏；私密改公开必须重新提交审核。不得由前端自行改已审核状态。
4. 私密信不接受其他人的回信。作者自己的“允许回信”设置在恢复公开时如何恢复，由接口明确；前端目前记住切换前的选择，私密请求实际关闭回信。
5. 已公开信仅改 allowReplies 时应保持公开；修改正文／标题等内容继续审核。当前交接代码会对所有字段变更执行下架，需区分。
6. 原信变私密或被删除，不连带删除其他作者已公开的回信；原信链接返回 404 时由前端提示“原信暂时无法查看”。
7. 同步数据库约束。原有 wall/public 与 user/private 的绑定约束不能直接表达“仅自己可见”；后端应明确作者私密保存的模型，不能只接受一个新字段而沿用旧权限判断。

以上为本轮新需求，并不意味着之前后端未按旧约定交付。前端尚未向真实接口发送这个新增字段，也未修改后端代码。

## 给 UI 同学

不需要画设置中心。写信页增加一个可见范围选择和一个回信开关即可；未保存提醒、删除确认沿用前端统一弹窗。继续提供核心页面和独立素材。
