# 珞珈烟火邮局 · 时光信笺日历功能说明

## 1. 本轮任务

1. 将独立日历设计稿接入正式 `frontend` SPA。
2. 使用真实登录用户的信件数据，不保留写死的示例信件。
3. 提供“日历”和“时间轴”两种查看方式。
4. 保持现有登录、权限、私密信和审核规则不变。
5. 完成桌面端与移动端基础适配。

## 2. 已完成功能

1. 正式路由：`/frontend/#/calendar`。
2. 首页“时光信笺”和信箱页导航均可进入。
3. 日历支持：

   - 上月、下月切换。
   - 有信日期显示金色圆点。
   - 今天、选中日期分别标记。
   - 同一天展示多封信。
   - 无信日期显示空状态。

4. 时间轴按投递时间从新到旧排列全部有效信件。
5. 日历和时间轴中的信件均可进入详情。
6. 未登录时显示登录引导；没有寄出信件时显示写信引导。
7. 日期按 `Asia/Shanghai` 计算；后端无时区的 UTC 时间也会正确转换。

## 3. 数据口径

1. 展示：`pendingReview`、`published`、`private`。
2. 不展示：`draft`、`returnedForEdit`、已删除信件。
3. 公开信按 `submittedAt` 归档。
4. 私密信按 `createdAt` 归档。
5. 私密信仍只对作者和指定收件人开放；本页只读取作者自己的列表。

## 4. 接口变化

1. 继续使用 `GET /api/v1/me/letters`，无需新增数据表或迁移。
2. `MyLetterSummary` 新增：

   - `createdAt`
   - `updatedAt`

3. 页面以每页 50 封自动读取全部个人信件，并在本次登录会话中缓存。
4. 保存、提交或退出登录后缓存自动失效。

## 5. 主要文件

1. `frontend/calendar.js`：日期转换、有效信件筛选、按日期分组。
2. `frontend/app.js`：日历与时间轴页面、路由和真实数据接入。
3. `frontend/app.css`：日历、时间轴和响应式样式。
4. `frontend/index.html`：时光信笺导航入口。
5. `script.js`：首页入口跳转。
6. `tests/calendar.test.mjs`：时区、状态筛选和同日分组测试。

## 6. 验收方式

1. 启动 FastAPI 和 `npm run dev:api`。
2. 普通用户寄出一封公开信或私密信。
3. 打开 `http://127.0.0.1:4173/frontend/#/calendar`。
4. 确认对应日期出现圆点，点击后能看到并打开该信。
5. 切换“时间轴”，确认最新投递排在最前。
6. 保存一封草稿，确认它不会出现在时光信笺。

## 7. 暂不包含

1. 按关键词搜索。
2. 服务端专用日历聚合接口。
3. 超过 5000 封个人信件的归档加载。
4. 定时信与未来送达日期。
