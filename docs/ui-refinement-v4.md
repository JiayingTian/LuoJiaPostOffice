# V4 修改与联调说明

> **历史资料**：本文记录早期设计或接口约定，不是当前参赛演示的操作说明。当前 GitHub Pages 与 `npm run dev` 使用演示模式，公开信寄出后直接展示；`npm run dev:api` 接入的真实后端仍保留管理员审核。请以仓库根目录 README 和当前源码为准。

> 同步记录（2026-10-20）：本仓库已同步正文 2000 字上限、公开信收回草稿、固定原因退回审核，以及指定用户私密投递。

## 本次前端修改

- 管理员审核可以通过，或选择一个固定原因退回作者草稿箱；作者在草稿详情中看到未通过原因。
- 已公开信件的作者可点“再次编辑”。先确认“收回草稿箱，再继续写？”，确认后收回，保留原文和信件 ID；取消不改状态。修改后重新提交审核，不能直接恢复公开。
- 正文上限 2000，草稿和提交都校验；当前仍保留提交最少 20 字、标题 2–80 字。按 Unicode 码点计数，标点、空格和换行也计入；常用单码点 Emoji 算 1，多码点组合可能超过 1。
- 删除“纯文字信件，保留自然换行”和写信页的“草稿只保存在此浏览器；关闭前请先保存。”提示。
- “署名”移除“选填”，与“匿名展示”并列；不因此新增署名必填要求。匿名只影响署名，不代表私密。
- 公开选项改为“公开 · 与人分享”；预览仍说明提交审核，避免误解为即时公开。
- 新信默认允许回信；已保存信件沿用作者原设置，不覆盖已有关闭选择。私密信仍不接收回信。
- 离开提醒改为“保存 / 暂不保存 / 继续编辑”，解释暂不保存将丢失本次未保存修改。删除确认仍为“删除 / 取消”。
- 品牌左侧改为棕色校园建筑 SVG 剪影，作为临时图标，正式地标轮廓由 UI 同学确认；不是官方校徽。

## 请后端同步或确认

1. 正文最大长度统一为 2000：创建、更新、提交审核校验、OpenAPI、错误文案及相关测试；2000 能保存和提交，2001 返回字段错误。前端已改，不代表后端同步完成。
2. 当前前端收回已公开信件调用 `PATCH /letters/{id}`，发送原 title 和 `submitForReview:false`。依据现有本地接口实现：显式更新 title 会使已公开信转 draft，清空 publishedAt/submittedAt，保留正文和 ID。请确认你们最新版本仍支持此行为；如已改为只识别实际内容差异，请明确收回接口，不能仅靠前端隐藏。
3. 收回后公共列表和非作者详情不可读，作者草稿箱可读可编辑；重新提交后仍须审核。已存在的回信不能随原信被删除；原信不可访问时按权限返回。联调请用两个普通用户验证。
4. `returnForEdit` 只接受约定的五个原因标签，执行后 `status=draft`，并清空 `submittedAt` 与 `publishedAt`。
5. 私密信是“指定用户投递”，只允许作者和该收件人读取；不进入审核，管理员也不能借角色读取。
